# pyOpenSSL: NOT A FEATURE, A REPAIR, and the clearest argument this file holds
# for running `.\fd-manager.ps1 lock`.
#
# The image resolved cryptography 50.0.2 beside pyOpenSSL 24.3.0, and those two
# cannot live together: pyOpenSSL 24.x still defines a class X509Extension
# whose body reads _lib.GEN_EMAIL, a binding cryptography has since removed.
# The class fails AT IMPORT, so everything that touches OpenSSL.crypto falls --
# and botocore is merely the first to, through urllib3.contrib.pyopenssl. The
# traceback blames boto3 and boto3 is innocent.
#
# pyOpenSSL 25.0 removed X509Extension outright, which is exactly the repair.
#
# HOW THE MISMATCH GOT IN, because the mechanism matters more than the fix: the
# floors in this file let pip resolve cryptography to its newest while
# pyOpenSSL came in pinned by Airflow. Floors are still the right default here
# -- the comment at the top of this file says why -- but they make M8's lock
# the thing that holds a working set together, not a formality. This defect sat
# in the image unnoticed from the day it was built, because nothing had yet
# imported OpenSSL.crypto.
pyopenssl>=25.0
